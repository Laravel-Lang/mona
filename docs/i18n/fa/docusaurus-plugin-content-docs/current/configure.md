Mona تنظیمات پیش‌فرض را خودکار بارگذاری می‌کند. فایل‌هایی را که می‌خواهید تغییر دهید، در پوشهٔ `config/` برنامه منتشر کنید.

```bash
php artisan vendor:publish --tag=localization_main
```

برچسب `localization` هر پنج فایل را منتشر می‌کند. نام هر فایل بدون `.php` هم برچسب انتشار است و هم کلید پیکربندی Laravel.

| فایل | تنظیمات |
| --- | --- |
| `localization_main.php` | سبک‌های ترجمه، نام‌های مستعار و فیلترهای انتشار |
| `localization_punctuation.php` | نشانه‌گذاری هوشمند و گیومه‌های ویژهٔ هر زبان منطقه‌ای |
| `localization_routes.php` | [نام مسیرها، منابع زبان منطقه‌ای و میان‌افزارها](./routes.md) |
| `localization_models.php` | [پسوند مدل ترجمه، فیلترها و مسیرهای تولید فایل](./models.md) |
| `localization_map.php` | فرادادهٔ زبان منطقه‌ای، مانند خط، منطقه و جهت نوشتار |

Laravel هر تنظیم سطح بالا را با مقدار برنامه جایگزین می‌کند. هنگام ویرایش آرایهٔ `locales` در `localization_punctuation.php`، پیش‌فرض‌های زبان‌های منطقه‌ای را که هنوز نیاز دارید نگه دارید.

پس از تغییر پیکربندی، اگر حافظهٔ نهانی وجود دارد، آن را با `php artisan config:clear` پاک کنید. `php artisan lang:update` را اجرا کنید تا ترجمه‌های متأثر از تنظیمات انتشار دوباره تولید شوند.

## سبک‌های ترجمه {#translation-styles}

سبک ترجمه واژه‌نامه‌ای نام‌دار است که عبارت‌بندی متن‌های انتخابی را تغییر می‌دهد. برای نمونه، یک بسته می‌تواند `informal.json` را برای لحن دوستانه یا `john.json` را برای عبارت‌بندی یک محصول ارائه کند. نام سبک‌ها مستقل از کد زبان منطقه‌ای، نام برنامه و نام بسته است. هر بستهٔ ترجمه می‌تواند برای زبان‌هایی که پوشش می‌دهد در `locales/<locale>/<style>.json` سبک ارائه کند. سبک می‌تواند تنها یک عبارت داشته باشد. کاربرد اولیه، شیوه‌های غیررسمی خطاب به کاربر بود. [بحث دربارهٔ ترجمه‌های غیررسمی](https://github.com/orgs/Laravel-Lang/discussions/124)

پس از نصب افزونه‌ای که سبک `john` را ارائه می‌دهد، آن را در انتهای فهرست در `config/localization_main.php` بگذارید تا در هر منبع واژه‌نامه اولویت داشته باشد.

```php
'styles' => ['default', 'informal', 'john'],
```

با اجرای `php artisan lang:update`، Publisher فایل‌های سبک هر زبان منطقه‌ای نصب‌شده را ادغام می‌کند. برای هر عبارت، اگر `john` آن را ارائه کند اولویت دارد، سپس `informal` و پس از آن `default`. برای نمونه، بستهٔ فرانسوی می‌تواند عبارتی را در `locales/fr/john.json` عوض کند و همان عبارت در آلمانی از `locales/de/informal.json` یا `locales/de/default.json` خوانده شود. Publisher ترتیب را جداگانه برای Library مشترک و بسته‌ای که فایل را ارائه می‌کند اعمال می‌کند. برای آن فایل، عبارت منطبق از بسته بر مدخل Library اولویت دارد.

تنظیم پیش‌فرض `['default', 'inline']` است. سبک `inline` پیام‌های عمومی اعتبارسنجی مانند «این فیلد باید پذیرفته شود» را ارائه می‌کند. برای استفادهٔ صرف از عبارت‌بندی استاندارد، `styles` را روی `['default']` بگذارید. اگر `default` را از فهرست حذف کنید، Publisher آن را به ابتدای فهرست اضافه می‌کند.

## نام‌های مستعار زبان منطقه‌ای {#locale-aliases}

`localization_main.aliases` را به‌صورت نگاشتی از کدهای استاندارد به نام‌های مستعار تنظیم کنید. برای نمونه، مدخل زیر را به آرایهٔ برگشتی در `config/localization_main.php` اضافه کنید.

```php
'aliases' => [
    'de_CH' => 'de-CH',
],
```

Artisan می‌تواند `de-CH` را بپذیرد، اما Laravel و فایل‌های منتشرشده از `de_CH` استفاده می‌کنند. `APP_LOCALE` و `APP_FALLBACK_LOCALE` را روی کدهای استاندارد بگذارید. برای نمونه‌های تبدیل و جست‌وجو به [زبان‌های منطقه‌ای و نام‌ها](./locales.md) مراجعه کنید.

تطبیق نام مستعار به بزرگی و کوچکی حروف حساس است. برای هر زبان منطقه‌ای نام مستعار یکتایی انتخاب کنید که با کد استاندارد دیگر زبان‌ها یکسان نباشد.

## مستثنا کردن فایل‌ها و الزام استفاده از یکپارچه‌سازی‌ها {#skip-files-and-force-integrations}

- `localization_main.skip` الگوهای `*` را بدون حساسیت به بزرگی و کوچکی حروف با مسیرهای کامل دارای جداکنندهٔ `/` تطبیق می‌دهد. می‌توان فایل‌های منبع، واژه‌نامه‌ها و مقصدهای انتشار را مستثنا کرد. برای نمونه، `['*/lang/fr/validation.php']` مانع نوشتن آن مقصد توسط Publisher در برنامه‌ای می‌شود که از `lang/` استفاده می‌کند.
- `localization_main.force` نام بسته‌های Composer را می‌پذیرد. به Publisher اجازه می‌دهد از مدخل‌های مانیفست حتی هنگامی استفاده کند که وابستگی نام‌برده وجود ندارد، نسخهٔ نصب‌شده منطبق نیست یا نام پروژهٔ ریشه متفاوت است. هنگامی از آن استفاده کنید که ترجمه‌های مانیفست برای برنامهٔ شما قابل استفاده‌اند.

`skip` بر `force` اولویت دارد.

## نشانه‌گذاری هوشمند {#smart-punctuation}

با تنظیم `LOCALIZATION_PUNCTUATION_ENABLED=true`، گیومه‌ها، خط تیره‌ها و سه‌نقطه‌های مناسب حروف‌چینی را در ترجمه‌های منتشرشده فعال کنید. برای قواعد عمومی `localization_punctuation.common` و برای قواعد جایگزین هر زبان منطقه‌ای `localization_punctuation.locales` را با کلید کد استاندارد ویرایش کنید. این قواعد در نوبت بعدی نوشتن رشته‌ها توسط Publisher اعمال می‌شوند.

## فرادادهٔ زبان منطقه‌ای {#locale-metadata}

`localization_map.locales` کدهای استاندارد را به خط (`type`)، زبان منطقه‌ای (`regional`) و جهت نوشتار اختیاری (`direction`) نگاشت می‌کند. اگر جهتی تعیین نشده است، از `Direction::LeftToRight` استفاده کنید.

```php
use LaravelLang\LocaleList\Direction;

$metadata = config('localization_map.locales.ar', []);
$script = $metadata['type'];         // 'Arab'
$regional = $metadata['regional'];  // 'ar_AE'
$dir = ($metadata['direction'] ?? Direction::LeftToRight)->value; // 'rtl'
```
