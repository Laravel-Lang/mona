Mona автоматично завантажує типові налаштування. Опублікуйте файли, які хочете змінити, в каталозі `config/` застосунку.

```bash
php artisan vendor:publish --tag=localization_main
```

Тег `localization` публікує всі п'ять файлів. Назва кожного файла без розширення `.php` також слугує тегом публікування і ключем конфігурації Laravel.

| Файл | Налаштування |
| --- | --- |
| `localization_main.php` | Стилі перекладу, аліаси й фільтри публікування |
| `localization_punctuation.php` | Автоматична типографіка та лапки для окремих локалей |
| `localization_routes.php` | [Назви маршрутів, джерела локалі й мідлвар](./routes.md) |
| `localization_models.php` | [Суфікс моделі перекладу, фільтрування та шляхи генератора](./models.md) |
| `localization_map.php` | Метадані локалей, як-от писемність, регіон і напрямок письма |

Laravel замінює кожен параметр верхнього рівня значенням із конфігурації застосунку. Якщо редагуєте масив `locales` у `localization_punctuation.php`, збережіть ті стандартні правила для локалей, які ще потрібні.

Після зміни налаштувань очистьте наявний кеш конфігурації командою `php artisan config:clear`. Щоб згенерувати заново переклади, на які впливають параметри публікування, виконайте `php artisan lang:update`.

## Стилі перекладу {#translation-styles}

Стиль перекладу — це іменований словник, який змінює формулювання вибраних фраз. Наприклад, пакет може надавати `informal.json` для невимушеного тону або `john.json` для термінології певного продукту. Назви стилів не залежать від кодів локалей, назв застосунків і пакетів. Будь-який пакет перекладів може надати стиль у файлі `locales/<locale>/<style>.json` для підтримуваних мов. Стиль може містити навіть одну фразу. Початково ця можливість призначалася для неформальних форм звертання. [Обговорення неформальних перекладів](https://github.com/orgs/Laravel-Lang/discussions/124)

Після встановлення плагіна зі стилем `john` додайте цей стиль наприкінці списку в `config/localization_main.php`, щоб надати йому пріоритет у кожному джерелі словників.

```php
'styles' => ['default', 'informal', 'john'],
```

Під час виконання `php artisan lang:update` Publisher об'єднує файли стилів для кожної встановленої локалі. Для кожної фрази пріоритет має `john`, якщо він містить цю фразу, потім `informal`, а тоді `default`. Наприклад, французький пакет може перевизначити одну фразу у файлі `locales/fr/john.json`, а німецький використає для цієї ж фрази `locales/de/informal.json` або `locales/de/default.json`. Publisher застосовує цей порядок окремо до спільного пакета Library і пакета, що надає файл. Для цього файла відповідна фраза з пакета має пріоритет над записом Library.

Типове налаштування — `['default', 'inline']`. Стиль `inline` надає універсальні повідомлення перевірки, як-от «Це поле потрібно прийняти». Укажіть `['default']` у `styles`, щоб використовувати лише стандартні формулювання. Якщо `default` відсутній у списку, Publisher додає його на початок.

## Аліаси локалей {#locale-aliases}

Укажіть у `localization_main.aliases` відповідності між канонічними кодами та аліасами. Наприклад, додайте такий запис до масиву, який повертає `config/localization_main.php`.

```php
'aliases' => [
    'de_CH' => 'de-CH',
],
```

Artisan приймає `de-CH`, а Laravel та опубліковані файли використовують `de_CH`. Використовуйте канонічні коди в `APP_LOCALE` і `APP_FALLBACK_LOCALE`. Приклади перетворення та пошуку наведено на сторінці [Локалі й назви](./locales.md).

Під час зіставлення аліасів враховується регістр. Для кожної локалі вибирайте унікальний аліас, який відрізняється від канонічних кодів інших локалей.

## Виключення файлів і примусове підключення інтеграцій {#skip-files-and-force-integrations}

- `localization_main.skip` зіставляє шаблони `*` з повними шляхами, що мають роздільники `/`, без урахування регістру. Він дає змогу виключити вихідні файли, словники та цільові файли публікування. Наприклад, `['*/lang/fr/validation.php']` забороняє Publisher записувати цей файл у застосунку, що використовує `lang/`.
- `localization_main.force` приймає назви пакетів Composer. Він дає змогу Publisher обробити записи маніфесту, навіть якщо вказаної залежності немає, встановлена версія не відповідає вимогам або назва кореневого проєкту відрізняється. Використовуйте цей параметр, якщо переклади з маніфесту підходять для вашого застосунку.

`skip` має пріоритет над `force`.

## Автоматична типографіка {#smart-punctuation}

Установіть `LOCALIZATION_PUNCTUATION_ENABLED=true`, щоб використовувати типографські лапки, тире та три крапки в опублікованих перекладах. Змінюйте загальні правила в `localization_punctuation.common`, а винятки для окремих локалей — у `localization_punctuation.locales`, використовуючи канонічні коди як ключі. Ці правила застосуються до опублікованих рядків під час наступного запису через Publisher.

## Метадані локалей {#locale-metadata}

`localization_map.locales` зіставляє канонічні коди з системою письма (`type`), регіональною локаллю (`regional`) і необов’язковим напрямком письма (`direction`). Якщо напрямок не задано, використовуйте `Direction::LeftToRight`.

```php
use LaravelLang\LocaleList\Direction;

$metadata = config('localization_map.locales.ar', []);
$script = $metadata['type'];         // 'Arab'
$regional = $metadata['regional'];  // 'ar_AE'
$dir = ($metadata['direction'] ?? Direction::LeftToRight)->value; // 'rtl'
```
