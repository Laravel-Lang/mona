Publisher входить до офіційних пакетів перекладів. Його команди Artisan записують переклади PHP та JSON до мовного каталогу застосунку, зазвичай `lang/`. Файли окремих пакетів також можуть записуватися до `lang/vendor/`.

## Додавання локалей {#add-locales}

Передайте один або кілька [кодів локалей](./available-locales.md), розділених пробілами. На вході приймаються налаштовані аліаси, а створені файли використовують канонічні коди.

```bash
php artisan lang:add fr de_CH
```

Команда створює каталоги локалей, а потім оновлює **всі встановлені локалі**, зокрема поточну та резервну локалі застосунку. Якщо аргументів немає, вона запитує, чи встановити всі підтримувані локалі. В автоматизації передавайте коди явно.

## Оновлення перекладів {#update-translations}

```bash
php artisan lang:update
```

Publisher визначає локалі за поточною та резервною локалями застосунку, файлами або каталогами в корені мовного каталогу й файлами JSON у `lang/vendor/<package>/`. Самого каталогу перекладів PHP залежності недостатньо, щоб локаль вважалася встановленою. Використайте `lang:add` для цієї локалі, щоб створити її каталог у застосунку.

Пакети перекладів оголошують підтримувані пакети, версії та цільові файли в [маніфестах плагінів](./plugins.md). Publisher об'єднує спільні словники зі словниками пакета та записує об'єднані переклади до кожного цільового файла. Він зберігає сторонні ключі й замінює значення збіжних ключів, зокрема числових. Якщо фрази немає у словниках, Publisher записує вихідну фразу. Зберігайте власні перевизначення в окремих файлах перекладів або [виключіть](./configure.md#skip-files-and-force-integrations) згенеровані цільові файли, які ви підтримуєте самостійно.

Виконайте `lang:update` після зміни залежностей Composer або [параметрів публікування](./configure.md). Перегляньте отримані зміни.

## Видалення локалей {#remove-locales}

```bash
php artisan lang:rm de_CH
```

Команда видаляє каталог і файл JSON канонічного коду локалі з кореня мовного каталогу та з кожного безпосереднього каталогу `lang/vendor/<package>/` разом з усіма власними файлами всередині. Поточну та резервну локалі захищено. Якщо аргументів немає, команда запитає, чи видаляти всі незахищені локалі. Типова відповідь — «ні». Якщо каталог локалі є посиланням, команда видаляє саме посилання.

Команда виводить `DONE`, `PROTECTED`, `INVALID`, `SKIP` або `FAILED` для кожної локалі. Якщо після спроби видалення залишився файл або каталог, команда показує його шлях і повертає код помилки. Перевіряйте стан кожної локалі, бо `PROTECTED`, `INVALID` і `SKIP` можуть супроводжувати код успішного завершення.

## Резервні переклади JSON {#json-fallback}

Пакет `laravel-lang/json-fallback` додає пошук у JSON-файлі резервної локалі перед переходом до перекладів PHP, коли ключа немає в JSON. Пакет входить до Common. Щоб установити його окремо, виконайте `composer require laravel-lang/json-fallback`.

Додайте `LaravelLang\JsonFallback\LangJsonFallbackServiceProvider::class` до сервіс-провайдерів застосунку в `bootstrap/providers.php`. Якщо застосунок явно реєструє `Illuminate\Translation\TranslationServiceProvider`, замініть цей запис провайдером Mona. [Реєстрація сервіс-провайдерів Laravel](https://laravel.com/docs/13.x/providers#registering-providers)

Якщо поточна локаль французька, а резервна — англійська, для ключа, відсутнього в `lang/fr.json`, тепер можна отримати значення з `lang/en.json`.
