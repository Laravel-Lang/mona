Mona аўтаматычна загружае налады па змаўчанні. Апублікуйце файлы, якія трэба змяніць, у каталог `config/` вашага прыкладання.

```bash
php artisan vendor:publish --tag=localization_main
```

Тэг `localization` публікуе ўсе пяць файлаў. Імя кожнага файла без `.php` таксама служыць тэгам публікацыі і ключом канфігурацыі Laravel.

| Файл | Налады |
| --- | --- |
| `localization_main.php` | Стылі перакладу, аліясы і фільтры публікацыі |
| `localization_punctuation.php` | Разумная пунктуацыя і двукоссе для асобных лакаляў |
| `localization_routes.php` | [Імёны маршрутаў, крыніцы лакалі і мідлвар](./routes.md) |
| `localization_models.php` | [Суфікс мадэлі перакладаў, фільтраванне і шляхі генератара](./models.md) |
| `localization_map.php` | Метаданыя лакаляў: пісьмо, рэгіён і кірунак тэксту |

Laravel замяняе налады верхняга ўзроўню значэннямі з праграмы. Пры рэдагаванні масіву `locales` у `localization_punctuation.php` захавайце тыя стандартныя перавызначэнні лакаляў, якія яшчэ патрэбныя.

Пасля змены налад ачысціце наяўны кэш канфігурацыі камандай `php artisan config:clear`. Выканайце `php artisan lang:update`, каб нанова згенераваць пераклады, на якія ўплываюць налады публікацыі.

## Стылі перакладу {#translation-styles}

Стыль перакладу — гэта слоўнік з уласным імем, які змяняе фармулёўкі асобных фраз. Напрыклад, пакет можа прапаноўваць `informal.json` для сяброўскага тону або `john.json` для фармулёвак канкрэтнага прадукту. Імёны стыляў не залежаць ад кодаў лакаляў, імёнаў прыкладанняў і пакетаў. Любы пакет перакладаў можа дадаць стыль у `locales/<locale>/<style>.json` для моў, якія падтрымлівае. Стыль можа змяшчаць нават адну фразу. Першапачаткова стылі ўвялі для нефармальных формаў звароту. [Абмеркаванне нефармальных перакладаў](https://github.com/orgs/Laravel-Lang/discussions/124)

Пасля ўсталявання плагіна, які дае `john`, пастаўце гэты стыль апошнім у `config/localization_main.php`, каб ён меў прыярытэт у кожнай крыніцы слоўніка.

```php
'styles' => ['default', 'informal', 'john'],
```

Калі вы запускаеце `php artisan lang:update`, Publisher аб’ядноўвае файлы стыляў для кожнай усталяванай лакалі. Калі фраза ёсць у `john`, выкарыстоўваецца яна. Далей ідуць `informal` і `default`. Напрыклад, французскі пакет можа перавызначаць адну фразу ў `locales/fr/john.json`, а нямецкі для той жа фразы выкарыстае `locales/de/informal.json` або `locales/de/default.json`. Publisher прымяняе гэты парадак асобна да агульнага слоўніка Library і да пакета, які дадае файл. Для гэтага файла фраза з пакета мае прыярытэт перад запісам з Library.

Налада па змаўчанні — `['default', 'inline']`. Стыль `inline` дае агульныя паведамленні праверкі, напрыклад «Гэта поле трэба прыняць». Задайце `styles` значэнне `['default']`, каб выкарыстоўваць толькі стандартныя фармулёўкі. Калі ў спісе няма `default`, Publisher дадае яго ў пачатак.

## Аліясы лакаляў {#locale-aliases}

Задайце `localization_main.aliases` як адпаведнасць кананічных кодаў іх аліясам. Напрыклад, дадайце наступны запіс у масіў, які вяртаецца з `config/localization_main.php`.

```php
'aliases' => [
    'de_CH' => 'de-CH',
],
```

Artisan можа прымаць `de-CH`, а Laravel і апублікаваныя файлы выкарыстоўваюць `de_CH`. Для `APP_LOCALE` і `APP_FALLBACK_LOCALE` задавайце кананічныя коды. Прыклады пераўтварэння і пошуку ёсць у раздзеле [Лакалі і назвы](./locales.md).

Рэгістр у аліясах мае значэнне. Для кожнай лакалі выкарыстоўвайце асобны аліяс, які адрозніваецца ад кананічных кодаў іншых лакаляў.

## Выключэнне файлаў і прымусовае ўключэнне інтэграцый {#skip-files-and-force-integrations}

- `localization_main.skip` параўноўвае шаблоны `*` з поўнымі шляхамі з раздзяляльнікамі `/` без уліку рэгістра. Так можна выключыць зыходныя файлы, слоўнікі і мэтавыя файлы публікацыі. Напрыклад, `['*/lang/fr/validation.php']` не дае Publisher запісаць гэты файл у прыкладанні, якое выкарыстоўвае `lang/`.
- `localization_main.force` прымае імёны пакетаў Composer. З дапамогай гэтай налады Publisher можа выкарыстоўваць запісы маніфеста, нават калі названая залежнасць адсутнічае, усталяваная версія не супадае або каранёвы праект мае іншае імя. Выкарыстоўвайце наладу, калі пераклады з маніфеста падыходзяць вашаму прыкладанню.

Налада `skip` мае прыярытэт перад `force`.

## Разумная пунктуацыя {#smart-punctuation}

Задайце `LOCALIZATION_PUNCTUATION_ENABLED=true`, каб уключыць друкарскія двукоссі, працяжнікі і шматкроп’і ў апублікаваных перакладах. Рэдагуйце `localization_punctuation.common` для агульных правілаў і `localization_punctuation.locales` для выключэнняў паводле кананічных кодаў лакаляў. Правілы будуць прыменены да радкоў пры наступным запісе Publisher.

## Метаданыя лакалі {#locale-metadata}

`localization_map.locales` супастаўляе кананічныя коды з пісьмовасцю (`type`), рэгіянальнай лакаллю (`regional`) і неабавязковым кірункам пісьма (`direction`). Калі кірунак не зададзены, выкарыстоўвайце `Direction::LeftToRight`.

```php
use LaravelLang\LocaleList\Direction;

$metadata = config('localization_map.locales.ar', []);
$script = $metadata['type'];         // 'Arab'
$regional = $metadata['regional'];  // 'ar_AE'
$dir = ($metadata['direction'] ?? Direction::LeftToRight)->value; // 'rtl'
```
