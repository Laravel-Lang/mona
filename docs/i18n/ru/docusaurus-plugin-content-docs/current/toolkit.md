---
title: Toolkit для работы с переводами
description: Ведите, переносите и импортируйте исходники и словари переводов из локальной копии Mona.
---

Toolkit — инструмент командной строки для сопровождения пакетов переводов. Запускайте его из локальной копии Mona после установки корневых зависимостей Composer. Для публикации переводов в приложении Laravel используйте [команды Artisan](./translations.md).

```bash
composer install
php src/Toolkit/bin/toolkit list
php src/Toolkit/bin/toolkit migrate-locales --help
```

## Проверка состояния переводов {#check-translation-status}

```bash
php src/Toolkit/bin/toolkit status src/Lang
```

По умолчанию команда записывает `locales/<locale>/_status.json` в проекте. В отчёте перечислены записи, перевод которых совпадает с исходной фразой, с группировкой по стилю. Команда объединяет исключения из `locales/_settings.json` и `locales/<locale>/_settings.json` и удаляет пустые отчёты. Чтобы найти фразы, которых совсем нет в словаре, сравните его с исходными файлами пакета.

Укажите `--output-dir`, чтобы сохранять отчёты в виде файлов `<locale>.json` в отдельном каталоге. Команда использует текущий рабочий каталог как основу для относительных путей. Если каталога назначения ещё нет, команда создаёт его при записи первого отчёта.

```bash
php src/Toolkit/bin/toolkit status src/Library --output-dir=workbench/status
```

Добавьте фразы, которые намеренно совпадают с исходными, в `excludes` соответствующего файла `_settings.json`.

```json
{
  "excludes": ["Laravel"]
}
```

## Управление каталогами локалей {#manage-locale-directories}

```bash
php src/Toolkit/bin/toolkit create-locale src/Library
php src/Toolkit/bin/toolkit delete-locale src/Library
```

`create-locale` создаёт недостающие каталоги для всех канонических [кодов локалей](./available-locales.md). Новые каталоги пусты. `delete-locale` удаляет каждый каталог непосредственно в `locales/`, имя которого не входит в этот список. Проверьте каталог перед запуском, особенно если в нём используются алиасы локализаций или собственные коды.

## Удаление устаревших записей из словарей {#remove-obsolete-dictionary-entries}

```bash
php src/Toolkit/bin/toolkit sync:library src
php src/Toolkit/bin/toolkit sync:package path/to/translation-pack
```

- `sync:library` собирает исходные фразы из пакетов с манифестом `laravel_lang.json` в `src/` и перезаписывает словари в `src/Library/locales/`.
- `sync:package` читает каталог `source/` одного пакета и удаляет неиспользуемые записи из его каталога `locales/`. После очистки пустые словари удаляются.

Обе команды сохраняют существующие переводы используемых фраз и файлы с начальным подчёркиванием, например `_settings.json`. Добавляйте переводы новых фраз напрямую в словарь.

Без аргумента `sync:library` использует каталог `src/` рабочей копии, а `sync:package` — текущий каталог. Обе команды обрабатывают каталоги с каноническими кодами локалей.

## Перенос словарей прежнего формата {#migrate-legacy-dictionaries}

```bash
php src/Toolkit/bin/toolkit migrate-locales path/to/legacy-pack --target=path/to/new-pack/locales
```

Передайте пакет прежнего формата с каталогами `source/` и `locales/`. Параметр `--target` задаёт каталог для подкаталогов локалей. Без него команда автоматически использует `locales/` исходного пакета.

- Записи из `json.json` и `php.json` переносятся в `default.json`. Записи из `json-inline.json` и `php-inline.json` переносятся в `inline.json`.
- В JSON-словарях прежнего формата исходные фразы уже служат ключами. Для PHP-словарей команда заменяет вложенные ключи исходными фразами из PHP-файлов в `source/`.
- Записи из `_excludes.json` переносятся в список `excludes` файла `_settings.json` целевой локали.

Toolkit объединяет переводы с целевыми словарями. При совпадении ключей приоритет у перенесённого перевода. Если оба исходных формата содержат перевод одной фразы, используется PHP-словарь.

Команда сохраняет файлы в `source/` и удаляет успешно перенесённые словари прежнего формата и файлы исключений, даже если указан отдельный каталог назначения. Изменения приложения и манифеста плагина описаны в [руководстве по апгрейду](./upgrade.md).

## Импорт исходников из ZIP-архива {#import-sources-from-a-zip-archive}

```bash
php src/Toolkit/bin/toolkit download \
  --url=https://github.com/laravel/framework/archive/refs/heads/12.x.zip \
  --directory=workbench/downloads/framework/12.x \
  --paths=src/Illuminate/Translation/lang/en \
  --only-copy
```

- `--directory` задаёт итоговый каталог назначения. `--paths` можно повторять для каталогов, заданных относительно корня архива.
- Выбранные файлы PHP и JSON копируются в каталог назначения по именам файлов. Файлы PHP копируются побайтно. JSON-файлы с одним именем объединяются, при этом новые значения имеют приоритет.
- Без `--only-copy` Toolkit ищет поддерживаемые вызовы функций перевода с литеральными ключами. Если он находит фразы, то записывает исходный JSON-файл, названный по родительскому каталогу назначения. В примере это `framework.json`.
- Для команды требуется расширение ZIP для PHP. Она подготавливает изменения перед записью и пытается восстановить прежнее содержимое каталога назначения, если запись завершится ошибкой.

Параметры `--url` и `--directory` обязательны. Каталоги из `--paths` обходятся рекурсивно. Опустите `--paths`, чтобы только найти ключи переводов. Проверьте найденные ключи перед добавлением в пакет.
