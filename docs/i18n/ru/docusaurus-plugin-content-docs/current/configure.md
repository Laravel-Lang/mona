Mona автоматически загружает настройки по умолчанию. Опубликуйте в каталоге `config/` приложения файлы, которые хотите настроить.

```bash
php artisan vendor:publish --tag=localization_main
```

Тег `localization` публикует все пять файлов. Имя каждого файла без `.php` также служит тегом публикации и ключом конфигурации Laravel.

| Файл | Настройки |
| --- | --- |
| `localization_main.php` | Стили перевода, алиасы и фильтры публикации |
| `localization_punctuation.php` | Типографская пунктуация и кавычки для каждой локали |
| `localization_routes.php` | [Имена маршрутов, источники локали и мидлвари](./routes.md) |
| `localization_models.php` | [Суффикс модели перевода, фильтрация и пути генерации](./models.md) |
| `localization_map.php` | Метаданные локали: письменность, регион, направление письма |

Laravel заменяет каждый параметр верхнего уровня значением из конфигурации приложения. Если меняете массив `locales` в `localization_punctuation.php`, сохраните стандартные правила для локалей, в которых они ещё нужны.

После изменения настроек очистите существующий кеш конфигурации командой `php artisan config:clear`. Выполните `php artisan lang:update`, чтобы заново сгенерировать переводы с учётом настроек публикации.

## Стили перевода {#translation-styles}

Стиль перевода — именованный словарь, который задаёт формулировки для отдельных фраз. Например, пакет может содержать `informal.json` для дружелюбного тона или `john.json` для формулировок конкретного продукта. Имена стилей не зависят от кодов локалей, названий приложений и пакетов. Любой пакет переводов может предоставить файл `locales/<locale>/<style>.json` для поддерживаемых языков. Стиль может состоять даже из одной фразы. Первоначально стили предназначались для неформальных обращений. [Обсуждение неформальных переводов](https://github.com/orgs/Laravel-Lang/discussions/124)

После установки плагина, который предоставляет стиль `john`, поставьте этот стиль последним в `config/localization_main.php`. Тогда он получит приоритет в каждом источнике словаря.

```php
'styles' => ['default', 'informal', 'john'],
```

При выполнении `php artisan lang:update` Publisher объединяет файлы стилей для каждой установленной локали. Для каждой фразы Publisher сначала ищет перевод в `john`, затем в `informal` и затем в `default`. Например, пакет может переопределить одну фразу на французском в `locales/fr/john.json`, а для немецкого та же фраза может браться из `locales/de/informal.json` или `locales/de/default.json`. Publisher применяет этот порядок отдельно к общей библиотеке Library и пакету, предоставившему файл. Для этого файла совпадающая фраза из пакета имеет приоритет над записью из Library.

По умолчанию задано `['default', 'inline']`. Стиль `inline` содержит общие сообщения валидации, например «Это поле должно быть принято». Чтобы использовать только стандартные формулировки, задайте для `styles` значение `['default']`. Если пропустить `default`, Publisher добавит его в начало списка.

## Алиасы локализаций {#locale-aliases}

Укажите в `localization_main.aliases` соответствия канонических кодов алиасам. Например, добавьте следующую запись в массив, возвращаемый файлом `config/localization_main.php`.

```php
'aliases' => [
    'de_CH' => 'de-CH',
],
```

Artisan может принять `de-CH`, тогда как Laravel и опубликованные файлы используют `de_CH`. Задавайте для `APP_LOCALE` и `APP_FALLBACK_LOCALE` канонические коды. Примеры преобразования и поиска см. в разделе [Локали и названия](./locales.md).

При сопоставлении алиасов учитывается регистр. Выбирайте для каждой локали уникальный алиас, который не совпадает с каноническими кодами других локалей.

## Исключение файлов и принудительное подключение интеграций {#skip-files-and-force-integrations}

- `localization_main.skip` сопоставляет шаблоны с `*` с полными путями через разделитель `/` без учёта регистра. Можно исключать исходные файлы, словари и файлы назначения. Например, `['*/lang/fr/validation.php']` запрещает Publisher записывать этот файл в приложении с каталогом `lang/`.
- `localization_main.force` принимает имена пакетов Composer. Настройка позволяет Publisher использовать записи манифеста, даже если указанная зависимость отсутствует, установленная версия не совпадает с требуемой или имя корневого проекта отличается. Используйте её, когда переводы из манифеста подходят вашему приложению.

У `skip` приоритет выше, чем у `force`.

## Типографская пунктуация {#smart-punctuation}

Задайте `LOCALIZATION_PUNCTUATION_ENABLED=true`, чтобы включить типографские кавычки, тире и многоточия в опубликованных переводах. Общие правила настраиваются в `localization_punctuation.common`, а исключения по каноническим кодам локалей — в `localization_punctuation.locales`. Правила применятся к строкам при следующей публикации через Publisher.

## Метаданные локалей {#locale-metadata}

`localization_map.locales` сопоставляет канонические коды с письменностью (`type`), региональной локалью (`regional`) и необязательным направлением письма (`direction`). Если направление не задано, используйте `Direction::LeftToRight`.

```php
use LaravelLang\LocaleList\Direction;

$metadata = config('localization_map.locales.ar', []);
$script = $metadata['type'];         // 'Arab'
$regional = $metadata['regional'];  // 'ar_AE'
$dir = ($metadata['direction'] ?? Direction::LeftToRight)->value; // 'rtl'
```
